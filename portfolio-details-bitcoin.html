Bitcoin Price Prediction: Forecasting Price from On-Chain Activity

A regression study that predicts daily Bitcoin price from on-chain activity and compares Linear, Ridge and Lasso on a strict chronological split.

Project
Time-Series Regression & Model Comparison
Context
UIUC CS 598 — Practical Statistical Learning
Role
Sole author — data cleaning, feature engineering, modelling, evaluation
Stack
Python, scikit-learn, pandas, NumPy, mlxtend

Project Overview

What the numbers said

Best model: plain linear regression on a 7-day lag window — RMSE 978.4, against a mean-predictor baseline of roughly 5570, an error reduction of about 82%.

The surprise: Ridge came in at 1150.7 and Lasso at 2191.4. Shrinkage bought stability this dataset never needed, and Lasso’s L1 penalty dropped predictors that were carrying real signal.

What I Built

A time-series regression study for UIUC CS 598, Practical Statistical Learning, built in Python with scikit-learn, pandas, NumPy and mlxtend. The dataset holds 2,920 daily observations of Bitcoin network activity across 23 variables. I kept four, trade volume, transaction count, estimated USD transaction volume and output volume, and expanded each into lagged copies: 12 predictors at a 3-day window and 28 at 7 days. After forward-filling the gaps the lags create, I fit OLS with sequential forward selection, RidgeCV, LassoCV and a constant-mean baseline, and scored each by RMSE on the same held-out period.

Design Decisions

  • Split by date, 80/20. The test period always comes after the training period, so no model sees the future.
  • Change one thing at a time. Features and split stay fixed while the model changes, so RMSE differences come from the models.
  • Four variables I could explain, each run at 3-day and 7-day lags to measure what extra history adds.

The Result

Linear regression on the 7-day window had the lowest error, RMSE 978.4, about 82% below the mean baseline. Widening the window from 3 to 7 days cut its RMSE from 1384.6 to 978.4.

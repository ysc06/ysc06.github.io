Philly Restaurant Recommender

A ranking system that reads what diners wrote rather than what the listing claims — ~90,000 Yelp reviews, three retrieval algorithms, and four sentiment analyzers combined into one score.

Text Retrieval — NLP & Sentiment Analysis

Ranking Restaurants on Review Text Alone

Filtering restaurants by cuisine tag and price range is a database query, not a recommendation. So this system throws the metadata away and ranks on the only signal that carries an opinion: the reviews themselves. A free-text craving — “Japanese sushi” — is matched against the pooled review corpus of each of Philadelphia’s 200 most-reviewed restaurants, and that relevance score is combined with how positively those same ~90,000 reviews actually read. Relevance says the place serves what you asked for; sentiment says people were glad they went.

Project Overview

The pipeline, in numbers

200 restaurants, ~90,000 reviews, 3 retrieval algorithms and 4 sentiment analyzers — every one of the four scoring the same review, then reconciled on a common scale before either half of the ranking is allowed to speak.

Sentiment is aggregated per restaurant two ways: a plain average, and a weighted average that leans on reviewers with more history and more useful votes.

Restaurant metadata and user reviews were pulled from the Yelp Open Dataset, cleaned in Jupyter and OpenRefine, and narrowed to Philadelphia’s 200 most-reviewed restaurants. Each restaurant’s reviews are pooled into a single document, so a query is scored against everything diners have said about the place rather than any one review.

Four sentiment techniques run over all ~90,000 reviews — three lexicon-based (vaderSentiment, TextBlob, SentiWordNet) and one transformer-based (BERT). Their raw scores live on incompatible scales, so each is converted to a z-score, averaged across techniques, and normalized again before being weighed against the retrieval score.

The Challenge

Relevance and sentiment answer different questions and are measured in different units. A restaurant whose reviews mention sushi constantly may be mediocre; a beloved one may barely match the query at all. Combining the two means making them commensurable first — and four sentiment analyzers that disagree with each other make that harder, not easier.

My Approach

Treat analyzer disagreement as signal rather than noise: standardize each technique to z-scores so no scale dominates, average across all four, then renormalize the ensemble. Retrieval got the same skepticism — BM25, Word2Vec embeddings and pivoted length normalization were each implemented end to end so the ranking could be compared under a lexical, a semantic, and a length-corrected view of the same query.

Key Features

Everything between a raw Yelp dump and a ranked list of places to eat — the cleaning, the three retrieval models, the four-analyzer sentiment ensemble, and the score that reconciles them.

Free-Text Query, Not a Filter

Users describe what they want in their own words instead of ticking cuisine and price boxes. The query is scored against the pooled review text of each restaurant, so a phrase like “Japanese sushi” surfaces places diners actually describe that way — regardless of how the listing is categorized.

Three Retrieval Algorithms, Implemented in Parallel

BM25 for term-frequency saturation, pivoted length normalization to keep verbose restaurants from winning on volume, and Word2Vec embeddings to catch queries whose vocabulary never literally appears in a review. Each has its own preprocessing, vector-construction and search stage, so the three rankings can be compared head to head.

A Four-Analyzer Sentiment Ensemble

Three lexicon-based methods and one transformer score every review independently. Lexicons are fast and legible but brittle around negation and sarcasm; BERT reads context but costs orders of magnitude more compute. Running all four and averaging keeps any single method’s blind spot from setting a restaurant’s reputation.

z-Score Fusion Across Incompatible Scales

VADER’s compound score, TextBlob’s polarity, SentiWordNet’s lexical sums and BERT’s class probabilities share no common range. Each is standardized to a z-score, averaged across the four techniques, and renormalized — making the ensemble a genuine average of opinions rather than whichever analyzer happens to have the widest spread.

Reviewer-Weighted Aggregation

Alongside the plain per-restaurant average, a customized weighted average factors in reviewer signals carried through from the dataset — the user’s own rating, their lifetime average rating, review count, and useful votes — so a considered review from a prolific reviewer counts for more than a drive-by rating.

One Weighted Score, Top 10 / 25 / 50

Relevance and normalized sentiment are combined into a single weighted score, and restaurants are sorted from highest to lowest. The output is designed for a dashboard where a visitor types a craving, picks a list length, and gets a ranked shortlist — with example rankings for the query “Japanese sushi” checked in per algorithm.

Reproducible Data Pipeline

Yelp’s raw JSON is cleaned through staged notebooks plus an OpenRefine transform, with every intermediate written to CSV under a fixed folder layout and a pinned Python 3.8 Conda environment. Score distributions for all four analyzers are plotted across the full ~90,000-review corpus, so the ensemble’s inputs are inspectable rather than assumed.

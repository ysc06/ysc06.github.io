Philly Restaurant Recommender: Ranking Restaurants on Review Text Alone

Filtering restaurants by cuisine tag and price range is a database query, not a recommendation, and it ignores what diners actually said. This system ranks Philadelphia’s 200 most-reviewed restaurants on ~90,000 Yelp reviews alone, combining how well the reviews match a free-text query with how positively they read.

Project Overview

The pipeline, in numbers

200 restaurants, ~90,000 reviews, 3 retrieval algorithms and 4 sentiment analyzers — each of the four scores every review, then all four are put on a common scale before either half of the ranking counts.

Sentiment is combined per restaurant two ways: a plain average, and a weighted average that leans on reviewers with more history and more useful votes.

What I Built

This was a team project for CS410 Text Information Systems. Restaurant data and reviews came from the Yelp Open Dataset, cleaned through staged Jupyter notebooks and an OpenRefine transform and narrowed to Philadelphia’s 200 most-reviewed restaurants. Each restaurant’s reviews are pooled into one document, and a free-text query is scored against it with three retrieval algorithms built end to end: BM25 (rank-bm25), Word2Vec embeddings (gensim), and pivoted length normalization. Four sentiment analyzers score all ~90,000 reviews: vaderSentiment, TextBlob and SentiWordNet on the lexicon side, and BERT through transformers. Relevance and normalized sentiment then combine into a single weighted score that sorts the restaurants from highest to lowest.

Design Decisions

I ran four sentiment analyzers and treated their disagreement as signal, so no single method’s blind spot decides a restaurant’s reputation. Because their raw scores share no common range, each one is converted to a z-score, averaged across the four, and normalized again, which gives a real average of opinions instead of letting the widest-spread analyzer dominate. I also built three retrieval models side by side, so the same query can be ranked under a lexical, a semantic and a length-corrected view and compared head to head.

The Result

The pipeline takes a craving typed in plain words and returns a ranked top 10, 25 or 50 list of Philadelphia restaurants. Example rankings for the query “Japanese sushi” are checked in for each of the three algorithms, and score distributions for all four analyzers are plotted across the full ~90,000-review set.

Key Features

Free-text queries scored against each restaurant’s pooled reviews instead of cuisine and price filters; three retrieval algorithms (BM25, Word2Vec and pivoted length normalization) implemented in parallel; a four-analyzer sentiment ensemble fused by z-score; reviewer-weighted sentiment aggregation; one weighted score with top 10, 25 or 50 results; and a reproducible data pipeline with every intermediate step written to CSV in a pinned Python 3.8 Conda environment.
